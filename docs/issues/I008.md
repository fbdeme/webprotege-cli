title: "WebProtégé 라운드트립이 `@`가 든 리터럴(이메일)을 깨뜨림"
status: closed
---
심각도: high. [[overview/strengthening]]의 S1에 해당한다.

## 문제
plain literal `"user@dept.edu"`가 WebProtégé export에서 `"user"@dept.edu`로 나온다. 도메인이 언어 태그로 취급된 것이다. 점이 든 언어 태그는 Turtle/RDF 규칙 위반이라 rdflib가 파일을 거부한다. RDF/XML export에도 `xml:lang`으로 같은 손상이 있으므로 serializer 하나의 문제가 아니라 저장된 값 자체가 손상된 것이다. 실 PI 온톨로지를 올린 `cli test` 프로젝트의 export에서 40건(단순 39건, 임베디드 1건)이 나왔다.

이메일이 자유 텍스트 중간에 있으면(임베디드 케이스) 가짜 언어 태그 뒤에 원문이 이어진다.

```
:note "MMLab 2026/27 모집(중앙접수 mmlab-contact"@e.ntu.edu.sg, NPGS 무본드). ;
```

도메인까지만 재결합하면 `, NPGS 무본드).`가 따옴표 밖에 남고, `,`가 Turtle objectList 구분자로 읽혀 `Bad syntax (objectList expected)`로 파싱이 멈춘다.

## 원인
WebProtégé가 `@` 뒤를 언어 태그로 해석해 저장한다.

## 해결
- `onto`는 파일을 읽을 때 새니타이저를 돈다. `"…"@<점이 든 태그>`를 따옴표 안으로 재결합하고, 문장 끝 종결자(`;`, `.`, `,`)까지 이어지는 원문도 따옴표 안으로 끌어들인다. `cli test` export에서 40/40건이 복구되고(잔여 0), 임베디드 값도 원문 그대로 재구성된다. 회귀 테스트가 `test/onto_test.py`에 있다.
- 새니타이저는 안전망일 뿐 정식 경로가 아니다. 정식 경로는 git에 둔 캐노니컬 파일을 진실원으로 삼고 WebProtégé export를 편집 베이스로 쓰지 않는 것이다([[overview/hybrid-editing]]).
