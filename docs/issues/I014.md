title: "WebProtégé 라운드트립이 RDF reification(provenance)을 조용히 버림"
status: closed

심각도: high. [[overview/strengthening]]의 S7에 해당한다.

## 문제
실 PI 온톨로지(2,064 트리플)를 `wp create`로 올리고 다시 export한 파일(2,233 트리플)과 원본을 rdflib 트리플 단위로 set-diff하면 다음이 나온다.

- blank node가 없는 트리플은 하나도 사라지지 않았다. 추가된 247개는 모두 무해한 타입 선언이다(NamedIndividual 242, Datatype 3, AnnotationProperty 1, Class 1).
- 그러나 `rdf:subject`/`rdf:predicate`/`rdf:object`는 26개에서 0개가 되었다. reified statement 26개 × 3 = 78 트리플이 조용히 사라졌다.
- 원본 노드는 `rdf:Statement`, s/p/o, `asOf`/`source`/`verified`/`note`를 가진다. export 노드에는 어노테이션만 남고 s/p/o가 없어, provenance가 어떤 사실에 대한 것인지 알 수 없는 고아 노드가 된다.

클래스·속성·개체 수는 정상이고 export도 파싱 에러 없이 열리므로, blank node 수준 diff를 해야만 드러난다.

## 원인
WebProtégé 내부의 OWLAPI는 RDF reification을 OWL 구문으로 모델링하지 않는다. 업로드를 파싱할 때 `rdf:Statement` 노드의 어노테이션은 익명 개체로 남기지만 비-OWL인 s/p/o 포인터는 버린다. OWL 2에서 공리에 어노테이션을 다는 정식 방법은 `owl:Axiom`과 `owl:annotatedSource/Property/Target`인데, 원본은 `rdf:Statement`를 쓴다. WebProtégé의 한계이며 CLI 버그가 아니다.

## 해결
- `onto`의 `reified_statements()`가 `rdf:Statement`/`rdf:subject` 노드를 감지한다. `info`는 `reification: N node(s) — dropped by a WebProtégé round-trip` 줄을, `validate`는 `round-trip warning`을 출력한다(에러가 아니며 exit 0).
- `onto diff <A> <B>`가 이 set-diff를 정식 명령으로 만든다. blank node 없는 트리플은 정확히 비교하고, blank node 구조(reification, list, restriction)는 predicate별 개수로 비교하며, reification을 따로 검사한다. A의 단언이 B에 없으면 exit 1이다. 같은 파일끼리는 `IDENTICAL`(exit 0), 원본 대 재export는 reification 78 트리플 손실(exit 1)로 나온다.
- 운영 원칙: 캐노니컬 파일이 진실원이고 WebProtégé는 보기 전용(push만)이다([[overview/hybrid-editing]]).
- provenance를 `owl:Axiom`으로 인코딩하는 방안, `validate --profile owlapi-safe`, push 후 자동 `onto diff`는 아직 없으며 [[S002]]의 완료 조건에 들어 있다.
