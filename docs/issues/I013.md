긍정적 확인 결과를 기록한 이슈다.

## 문제
`add-disjoint`와 `add-characteristic`으로 만든 공리, 특히 blank node 기반 `owl:AllDisjointClasses`와 property characteristic이 `apply-edits`(MergeUpload)의 diff·저장·재export를 통과하는지 알 수 없었다. [[I008]]처럼 조용히 빠질 위험이 있었다.

## 확인 결과
합성 온톨로지(Cat/Dog/Fish, livesWith/age)로 create → apply-edits(공리 추가본) → export를 라이브 인스턴스에서 돌렸다.

- apply-edits 변경 수는 3이고, 추가한 OWL 공리 수(AllDisjointClasses 1, FunctionalProperty 1, SymmetricProperty 1)와 같다. WebProtégé는 트리플이 아니라 OWL 공리 단위로 diff한다.
- export에 `owl:AllDisjointClasses`와 `owl:members ( :Cat :Dog … )`, `owl:FunctionalProperty`, `owl:SymmetricProperty`가 모두 남아 있다.

따라서 공리 추가 명령은 파일 → WebProtégé 방향(push)에서 안전하다. 오프라인에서는 HermiT가 disjoint·functional 위반을 INCONSISTENT로 잡는 것도 실 PI 온톨로지 복사본으로 확인했다([[overview/hybrid-editing]]).
