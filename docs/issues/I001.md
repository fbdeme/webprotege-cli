title: "2019 이미지에 REST API가 없어 제어 표면을 알 수 없음"
status: closed
---
## 문제
CLI로 WebProtégé(`protegeproject/webprotege:latest`, `4.0.0-beta-3`)를 제어하려 했으나 공식 REST/HTTP API 문서가 없다. `WEB-INF/web.xml`에는 서블릿 매핑이 없고 catch-all 필터 하나(`WebProtegeWebAppFilter`)만 있다.

## 원인
`4.0.0-beta-3`는 GWT 앱이다. 모든 기능이 단일 GWT-RPC 서블릿 `/webprotege/dispatchservice`(`@RemoteServiceRelativePath("dispatchservice")`)의 `executeAction(Action)` 메서드 하나로 흐른다. 유일한 비-GWT 엔드포인트 `/download`도 인증된 세션이 있어야 하며, 세션 없이 요청하면 403을 돌려준다.

## 해결
- 후보 경로 프로빙: `/dispatch`, `/fileupload`, `/webprotege/dispatch`는 404이고 `/webprotege/dispatchservice`만 500(빈 본문, 엔드포인트 존재)을 돌려준다.
- JAR 디컴파일(CFR)로 액션 핸들러를 전수 확인한 결과 전부 GWT-RPC다.
- 결론적으로 HTTP 직접 호출 대신 헤드리스 브라우저 자동화를 택했다([[I002]], [[I003]]). 조사 절차와 결과는 [[overview/control-surface]]에 있다.
