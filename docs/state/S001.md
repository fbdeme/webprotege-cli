## 목표
self-host WebProtégé `4.0.0-beta-3`의 제어 표면을 사실로 확정하고, 그 위에서 프로젝트 가입·로그인·목록·생성·내보내기와 파일 편집 반영을 명령줄에서 할 수 있게 한다.

## 완료 조건
- 제어 표면 분석 결과가 `references/control-surface.md`에 있다([[overview/control-surface]]).
- `wp` CLI의 `signup`, `login`, `projects`, `create`, `export`, `apply-edits`가 라이브 인스턴스에서 동작한다.
- `onto.py` 구조화 편집 엔진이 동작하고 단위 테스트가 통과한다.
- export → `onto` 편집 → `wp apply-edits` 하이브리드 루프가 라이브 인스턴스에서 실증된다.

## 지금 상태
완료된 단계다.

- 대상 서버: 로컬 self-host WebProtégé `4.0.0-beta-3`, `http://localhost:5000`(`protegeproject/webprotege:latest`와 `mongo:4.0`을 docker compose로 띄움, `webprotege-selfhost` 런북 사용).
- 제어 표면: REST가 없고, 모든 기능이 GWT-RPC(`/webprotege/dispatchservice`)와 CHAP 인증, 다수의 커스텀 직렬화기를 거친다([[I001]], [[I002]], [[I003]]). 그래서 전송 수단으로 헤드리스 브라우저(Playwright)를 택했다([[overview]]).
- 구현: `WebProtegeClient`(`src/wp.js`)와 `wp` CLI(`src/cli.js`, commander). 셀렉터는 라이브 DOM에서 실측해 확정했다([[I005]]). export는 ZIP으로 저장한다([[I004]]).
- 편집 반영: Project ▸ Apply External Edits를 `wp apply-edits`로 자동화했다. 업로드 온톨로지 IRI가 프로젝트와 같아야 하고([[I006]]), 두 단계 다이얼로그를 모두 처리한다([[I007]]).
- `onto.py`(rdflib, owlready2): add-class/subclass/objprop/dataprop/individual/annotation, remove, validate(`--reason`은 HermiT), query. 없는 엔티티 참조는 거부하고 Ontology IRI를 보존한다. 단위 테스트 8/8.
- 검증: `npm test`(e2e) 통과. `test/fixtures/tiny.owl`(Widget, Gadget⊑Widget)을 올려 프로젝트를 만들고 Turtle로 export해 ZIP 안 `.ttl`에 클래스, subClassOf, label이 남아 있음을 확인한다. 하이브리드 루프는 create → export → `onto` 편집(`:Ghost` 참조 거부, Cog 추가, 추론 일관성) → `wp apply-edits` → 재export로 실증했다([[overview/hybrid-editing]]).
- 이어지는 작업은 [[S002]]에서 한다.
